# vrcnotifier 新手导读（写给完全不懂代码的人）

> 这份文档假设你：没写过代码，不认识任何术语。
> 我会尽量用生活里的东西打比方。看不懂的名词先跳过，后面会解释。

---

## 第 0 步：先给你吃颗定心丸

这个项目一共 1.7 万行代码，听着吓人，但**它真正在干的事只有一句话**：

> 盯着你在 VRChat 里的好友，谁上线了、谁下线了、谁换世界了，
> 就发一条消息到你 QQ 上。

剩下 99% 的代码，都是在处理「万一出错了怎么办」：

- 网断了怎么办？
- VRChat 把我的登录踢了怎么办？
- 同一个好友一秒内上下线三次，是不是要给你发三条骚扰消息？（不，要等 30 秒确认）
- 密钥丢了、数据库坏了怎么办？
- 消息发送失败了怎么办？

**所以新手读代码的正确心态是：先抓住那条主线，别被"防错代码"淹死。** 看到一堆 `try/catch`、`if (!xxx) return`，直接跳过去，那些是安全气囊，不是发动机。

## 第 1 步：这个项目像什么？（生活类比）

把它想象成一家**小小的快递公司**：

| 代码里的东西 | 类比 | 干什么的 |
|---|---|---|
| `src/pipeline.js` | 收货窗口 | 守着 VRChat 的实时消息管道，消息一来就收下 |
| `src/monitor.js` | 分拣中心主管 | 判断这条消息该不该处理、该通知谁 |
| `src/state.js` | 比对员 | 拿"之前的状态"和"现在的状态"对比，找出**变化** |
| `src/db.js` | 档案室 | 存好友名单、开关设置、加密后的账号密码 |
| `src/templates.js` | 写信员 | 把变化写成一句人话："小明 上线了" |
| `src/notify.js` + `src/qq.js` | 快递员 | 把信送到你的 QQ |
| `src/server.js` | 前台 + 展示厅 | 网页面板用的接口，浏览器找它要数据 |
| `public/app.js` | 展示厅的装修 | 你在浏览器里看到的那个界面 |
| `src/index.js` | 公司开业流程 | 早上开门：先把所有部门叫起来，按顺序接上电线 |

数据就像包裹，从左边进来，从右边出去。

## 第 2 步：全局地图

```
      VRChat 官方服务器
            │
   ┌────────┴─────────┐
   │                  │
 ①WebSocket         ②REST API
（实时推送，          （拉全量名单，
  消息很快）          一小时一次对账）
   │                  │
   ▼                  ▼
pipeline.js        vrcapi.js
   │                  │
   └────────┬─────────┘
            ▼
       monitor.js  ◄──── state.js（状态机：算出"变化"是什么）
            │
   ┌────────┼──────────┬──────────────┐
   ▼        ▼          ▼              ▼
 db.js   templates  world.js      server.js
（存档）  .js（写信） （查世界名）      │
            │                        ▼
            ▼                   public/app.js
       qq.js → QQ机器人 → 你手机    （网页面板）
```

**关键点：有两条通道，互为备份。**

- **① WebSocket（实时）**：VRChat 主动推消息给你，毫秒级。但它会漏消息、会断线。
- **② REST 对账（定时）**：每小时把好友名单整个拉一遍，跟数据库里的记录对比。这叫「**对账**」——像会计每天核对账本，防止实时通道漏掉了什么。

新手最容易困惑的地方："为什么同一个功能有两套代码？"——就是这个原因。你读代码时会看到 `handlePipelineEvent`（处理实时事件）和 `runSnapshot`（处理全量对账）两个入口，它们最后都会把结果交给同一套逻辑处理。

## 第 3 步：跟着一个"包裹"走完全程

**场景：你的好友「小明」上线了。**

1. **VRChat 推送**：一条 JSON 数据从 WebSocket 进来，大意是 `{type:"friend-online", user:{id:"usr_xxx", displayName:"小明"}}`
2. **`pipeline.js`**：收下原始数据，解析成对象，交给主管 → `monitor.handlePipelineEvent`
3. **`monitor.js`**：认出这是"好友事件"，找到小明的 ID，顺便去 `world.js` 问一下"他现在在哪个世界"（世界名要单独查，还有缓存）
4. **`state.js`**：比对！数据库里小明之前是 `offline`，现在变成 `online` → 得出结论：**变化类型 = "上线"**
5. **`db.js`**：查一下"小明这个好友，你开了上线通知吗？"没开 → 到此结束；开了 → 继续
6. **`templates.js`**：生成文案 `🟢 小明 上线了`
7. **`notify.js` → `qq.js`**：通过 QQ 官方机器人接口发给你的 QQ
8. **同时**：新状态写回数据库，并通过 SSE（服务器单向推送技术）告诉网页 → `public/app.js` 刷新好友列表

> 还有个细节叫 **pending（待定）**：下线通知不马上发。状态先记成"待定-下线"，等 30 秒。如果 30 秒内他又上线了，说明是网络抖动，这条通知就不发了。这就是 `state.js` 里 `pending_state` 那一堆逻辑，也是防止你被刷屏的关键。

## 第 8 步：小白专属 —— 本项目高频 JS 写法小词典

看到一个不懂的写法，回来查这张表。

### 1. `const` 和 `let`：装东西的盒子
```js
const name = '小明';   // 盒子贴上封条，不能再指向别的东西
let count = 0;         // 普通盒子，可以改
count = 1;             // ok
```
本项目里 `const` 远多于 `let`，因为大部分值一旦确定就不该改。老代码里的 `var` 现在已经不推荐用。

### 2. 函数：一段可以被反复使用的操作
```js
function add(a, b) { return a + b; }      // 传统写法
const add = (a, b) => a + b;               // 箭头函数写法，等价
```
`src/util.js:7` 的 `const p = (n) => String(n).padStart(2, '0');` 就是箭头函数。

### 3. 默认参数：不传就用自己的备胎
```js
function formatLocalTime(ts = Date.now()) { ... }   // src/util.js:5
```
不传 `ts` 就自动用"当前时间"。项目里到处都是这种写法。

### 4. 解构：从盒子堆里直接掏东西
```js
const { createDb } = require('./db');        // 从模块里只掏 createDb 这一个
function createLogger(defaultCategory = 'app', out = console.log) { ... }
```
更常见的组合拳（`src/util.js:83`）：
```js
function createLogger(defaultCategory = 'app', out = console.log)
```
以及参数表的解构 + 默认空对象（`src/filelog.js:43`）：
```js
function createFileLog({ dir, maxBytes = 2 * 1024 * 1024, maxFiles = 6 } = {}) { }
```
意思是：调用时传 `{ dir: 'xxx' }`，其余用默认值；连参数都不传也不会报错。

### 5. 模板字符串：把变量塞进句子
```js
const line = `[${formatLocalTime()}] [${level}] [${category}] ${body}`;
```
反引号 `` ` `` 包起来，`${...}` 里放任何表达式。等价于字符串拼接，但好读得多。

### 6. 对象和展开运算符 `...`
```js
const a = { x: 1, y: 2 };
const b = { ...a, y: 3 };   // 复制 a 的所有属性，然后把 y 覆盖成 3
```
`src/index.js:119` 的 `...(opts.monitor || {})` 就是"把用户传的配置合并进来，同一项以用户传的为准"。

### 7. 可选链 `?.` 和空值合并 `??`
```js
content.user?.id            // user 不存在就返回 undefined，而不是报错崩溃
const n = value ?? 500;     // value 是 null/undefined 才用 500；0 和 '' 会被当成有效值
```
对比 `||`：`value || 500` 会把 `0` 也换成 500，所以数字默认值必须用 `??`。项目里这句注释说得很清楚（`src/util.js:49`）：*"未设置的图片字段 VRChat 回空串，故用 `||` 而非 `??`"* —— **同一种场景，用哪个是故意的。**

### 8. 数组常用方法
```js
list.map(x => x.id)          // 每个元素变成 id，得到新数组
list.filter(x => x.on)       // 只保留满足条件的
list.includes('usr_1')       // 包不包含这个值 → true/false
list.find(x => x.id === id)  // 找第一个满足条件的元素
list.slice(-5)               // 取最后 5 个（src/logstream.js:45）
```

### 9. `async` / `await`：等一件慢事做完
```js
async function sendQq(user, change) {
  const result = await qq.sendText(...);   // 等发送完成，再往下走
  return result;
}
```
`async` 标记"这个函数里有慢操作"，`await` 表示"在这等到结果"。
**为什么需要它？** 网络请求要几百毫秒，如果傻等，整个程序就卡住了。`async/await` 让"等待"期间程序还能干别的事。

### 10. `try / catch`：防错气囊
```js
try {
  const data = JSON.parse(raw);   // 万一 raw 不是合法 JSON 呢？
} catch (e) {
  logger.warn('解析失败: ' + e.message);   // 出错不走崩，走这里
}
```
项目里满屏都是这个。**阅读时可以整块跳过**，只在需要知道"失败了会怎样"时再看。

### 11. `require` / `module.exports`：文件之间互相借用
```js
// util.js 最后一行：把东西借给别人
module.exports = { formatLocalTime, createLogger, maskKey };
```
```js
// 别的文件这样借
const { formatLocalTime } = require('./util');
```
**这是理解整个项目结构的钥匙**：`src/index.js` 顶部那一串 `require`，就是这家"公司"的部门清单。

### 12. 闭包 / 工厂函数：本项目最核心的写法
```js
function createLogStream({ capacity = 500 } = {}) {
  const entries = [];              // 私有变量，外面看不见
  function push(line) { entries.push(line); }
  return { push, tail, subscribe }; // 只暴露这几个方法
}
```
调用 `createLogStream()` 得到一个"日志流对象"，它内部藏着 `entries` 数组，外面碰不到。
**这就是 `createXxx()` 这个命名在本项目里反复出现的原因** —— 每个模块都是一个"工厂"，造一个能独立工作的部件，而不是一堆散落的全局函数。

## 第 9 步：读代码的通用方法（比语法更重要）

1. **先读文件头两行注释。** 本项目每个 `src/*.js` 开头都有一句"这个文件干嘛的"，作者写得很清楚。这一句能省你半小时。
2. **找"入口"和"出口"。** 文件末尾的 `module.exports` 告诉你"这个文件对外提供什么"；开头 `require` 的告诉你"它依赖谁"。
3. **先看测试文件。** `test/xxx.test.js` 里全是"输入 A 应该输出 B"的具体例子，读完就知道模块怎么用。
4. **函数优先读名字和返回语句**，中间的实现细节第一次可以先跳过。
5. **遇到看不懂的，先记下来往下走。** 回头看第二遍的时候，70% 的疑问会自动消失。
6. **不要试图一次读懂。** 第一遍目标只是"知道大概有什么"，第三遍才是"理解为什么这么写"。这是正常节奏，不是你不聪明。

## 附：这个项目里几个"作者的用心处"（读懂了会很有成就感）

- `src/util.js:49` 的注释解释了为什么用 `||` 而不是 `??` —— 这是踩过坑才写下的。
- `src/state.js` 的 `pending_state`：用"等 30 秒"换"不被刷屏"，是一个很聪明的取舍。
- `src/index.js:307` 附近：主密钥解不出来时会**清空数据然后自己重启**（`process.exit(0)`），靠 Docker 的 `restart: unless-stopped` 自动拉起来。这是"不让人手动干预"的设计。
- 两条通道（WebSocket + 定时对账）互相兜底，是这类监控程序的标准做法：**快通道负责实时，慢通道负责正确。**

# 附录 A：报错速查表（新手踩过的坑都在这里）

## 第一件事：学会读报错

Node 的报错有 90% 是噪音。**只看三个地方：**

```
ReferenceError: hello is not defined              ← ① 什么错（一句话）
    at subscribeAndNotify (file.js:435:6)          ← ② 文件:行号
```

然后往上看，Node 还会把出事的代码贴出来，**用 `^` 指着罪犯**：

```
/code/vrcnotifier/learn/02b-callbacks.js:435
  fn(hello)
     ^            ← 就是这个词出的问题
```

> **三步法：① 第一行的错误名 → ② `文件:行:列` → ③ `^` 指着哪个词**

中间那一堆 `at Module._compile`、`at Module._load` 叫**调用栈**，是"程序从哪儿一路调用过来"的路线图，新手直接忽略。

## 第二件事：常见报错对照

| 报错开头 | 真实含义 | 常见原因 | 怎么修 |
|---|---|---|---|
| `Cannot find module '/xxx/yyy.js'` | 找不到这个**文件** | 路径写错、多了个 `/`、少了目录层 | 敲 `pwd` 看自己在哪，`ls` 看文件在哪 |
| `Cannot find module 'react'`（没斜杠、没 `./`） | 找不到这个**第三方包** | 项目没装这个依赖 | 看 `node_modules/` 有没有；或删掉这行 import |
| `ReferenceError: xxx is not defined` | "你提到的 xxx 我没见过" | **忘了加引号**；或变量真没定义 | 检查是不是该写成 `'xxx'` |
| `TypeError: xxx is not a function` | "xxx 不是函数，你却给它加了括号" | 忘了 `return`；或"有括号 vs 没括号"搞混 | 看那个函数到底返回了什么 |
| `TypeError: Cannot destructure property ... of 'undefined'` | 解构了一个 `undefined` | 参数没传，但没写 `= {}` 兜底 | 参数末尾补上 `= {}` |
| `SyntaxError: Unexpected token` | 代码**语法**就不对 | 括号/引号/花括号不配对 | 看它指的那一行，往回找没闭合的符号 |
| `EADDRINUSE: address already in use` | 端口被占了 | 上次的服务没关掉 | 关掉旧进程，或换个 `PORT` |

## 第三件事：路径规则（`/` 开头 vs 不开头）

**这一条能消灭一大半 `Cannot find module`。**

| 你写的 | 类型 | 去哪里找 |
|---|---|---|
| `02-functions.js` | 相对 | 当前目录 |
| `learn/02-functions.js` | 相对 | 当前目录下的 `learn/` |
| `./learn/02-functions.js` | 相对（显式） | 同上 |
| `/learn/02-functions.js` | **绝对** | **磁盘最顶层**的 `learn/` ← 通常不存在 |
| `/code/vrcnotifier/learn/02-functions.js` | 绝对（完整） | 对 |

> **不以 `/` 开头 = 从"我现在站的地方"开始找**
> **以 `/` 开头 = 从"整块硬盘的最顶层"开始找**

**关键**：`/learn/...` 和 `learn/...` 是**两个完全不同的地方**，虽然只差一个字符。

回答"我在哪"的命令：

```bash
pwd     # 我在哪个目录
ls      # 这个目录里有什么
```

**还有个更快的办法：你的终端提示符里已经写着答案了。**

```
root@DESKTOP-2G3TSTJ:/code/vrcnotifier#
                    ^^^^^^^^^^^^^^^^^
                    @ 和 # 中间这一段就是当前目录
```

**以及最容易防错的技巧：敲 `node ` 之后按 `Tab` 键自动补全文件名。**

## 第四件事：项目里同一件事的应用

路径方向这件事，项目里用 5 行代码**防攻击**。见 `serve.js:33-36`：

```js
const file = path.normalize(path.join(base, p));
if (file !== base && !file.startsWith(base + path.sep)) {
  res.writeHead(403); res.end('Forbidden'); return;   // 越界 → 403 拒绝
}
```

如果不检查，用户在浏览器里请求 `/../../etc/passwd` 就能把服务器的密码文件下载走。
这 5 行的作用就是：**算出来的路径必须待在我允许的目录里面**。

**你遇到的"路径写错"和项目防的"路径越界"，是同一个知识点。**
